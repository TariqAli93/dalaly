## 1. بنية المشروع

مستودع pnpm workspace بثلاث حزم:

```
dalaly/
├── apps/
│   ├── renderer/      @dalaly/renderer   — Vue 3 + Vuetify 3 + Vite 7 (الواجهة)
│   └── desktop/       @dalaly/desktop    — Electron 39 (قشرة سطح المكتب)
├── server/            @dalaly/server     — Fastify 5 + Drizzle ORM + PostgreSQL
├── tools/cloudflared/                    — نفق الاتصال الخارجي (اختياري)
└── scripts/                              — سكربتات مساعدة
```

- **Package manager:** pnpm 10.28.0 (موجود `pnpm-lock.yaml` و`pnpm-workspace.yaml`).
- **Node:** المطلوب `>=20`، المتوفر على الجهاز v22.22.2.

### Frontend

- Vue 3.5 (`<script setup>` + TypeScript)، Vuetify 3.10 مع blueprint `md3`، لغة `ar` واتجاه RTL.
- Tailwind 4 مثبّت كإضافة Vite لكن الاعتماد الأساسي على Vuetify.
- التوجيه: `vue-router` بـ **`createWebHashHistory`** — أي أن المسارات في المتصفح تكون `‎/#/properties`‎ وليست `/properties`. (سبب الاختيار: Electron يحمّل الملفات عبر `file://`.)
- الحالة: composables عامة (`useAuth`, `useProperties`, `useLocations` …) بلا Pinia.
- التواصل مع الخادم: `fetch` عبر `services/api.service.ts` مع `Authorization: Bearer <token>`، والتوكن في `localStorage` تحت المفتاح `dalaly.session`.
- الجذر: `apps/renderer/src/main.ts` → `App.vue` → `router-view`.

### Backend

- Fastify 5 على `127.0.0.1:34567` (افتراضياً) بسابقة `/api`.
- Drizzle ORM على PostgreSQL، والـ migrations في `server/drizzle` تُشغَّل تلقائياً عند الإقلاع.
- الوحدات: `setup, auth, properties, images, followups, users, roles, permissions, stats, dashboard, locations, favorites, backup, import, remote-access`.
- المصادقة: **Username + PIN** (وليس كلمة مرور). قيود `zod`: PIN من 4 إلى 12 محرفاً، username ≥ 3 محارف. الجلسة توكن مُخزَّن مُجزَّأً في جدول `sessions` بصلاحية `SESSION_TTL_HOURS` (12 ساعة).
- الصلاحيات: RBAC كامل (29 صلاحية نظامية، دور `Super Admin` يملكها كلها).
- الصور: تُحفظ على القرص تحت `APP_DATA_DIR/images/properties/<propertyId>/` وصفوفها في `property_images`. تُقدَّم عبر `GET /api/properties/:id/images/:imageId/file?token=…`.

### قاعدة البيانات

PostgreSQL محلي على `127.0.0.1:5432`. القواعد الموجودة على الجهاز تشمل `dalaly` (قاعدة التطوير). أُنشئت لهذا العمل قاعدة **`dalaly_demo`** منفصلة تماماً.

## 3. هل يعمل التطبيق في المتصفح؟

**نعم — وبدرجة اعتماد عالية على HTTP لا على Electron.**

الواجهة تتحدث مع الخادم عبر `fetch` فقط. المسّ الوحيد بـ Electron يمرّ عبر جسر `preload.js` الذي يعرّض `window.dalalyConfig` بسبع دوال. جرد كامل لاستخدامها قبل التعديل:

| الملف                                          | الاستخدام                                          | تأثيره على الويب                                                                                   |
| ---------------------------------------------- | -------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `services/setup.service.ts`                    | `saveDatabaseUrl`                                  | يُتخطّى بأمان (الجسر غير معرّف)                                                                    |
| `utils/exportProperty.ts`                      | `exportPdf`                                        | كان يسقط إلى `window.open()` + `print()`                                                           |
| `components/setup/BackupSettings.vue`          | `chooseExportPath`, `pickFolder`, `pickBackupFile` | الأزرار كانت تختفي أو تُظهر خطأ                                                                    |
| `components/setup/ScheduledBackupSettings.vue` | `getScheduledBackup`, `saveScheduledBackup`        | كان يعرض تنبيهاً «متاح على سطح المكتب فقط» — وهو معطَّل أصلاً في `SettingsPage.vue` (السطر معلَّق) |

باقي التطبيق (الدخول، العروض، البحث، الفلاتر، الصور، المتابعات، المفضلة، المستخدمون، الأدوار، المواقع، النسخ الاحتياطي، الاستيراد/التصدير، سجل التغييرات، لوحة التحكم) لا يعرف بوجود Electron إطلاقاً.

### المشاكل التي كانت تمنع التشغيل على الويب

| #   | المشكلة                                                      | الأثر                                     |

| 1   | لا يوجد أمر لتشغيل الواجهة + الخادم كنسخة ويب                | يجب تشغيلهما يدوياً بأمرين منفصلين        |
| 2   | `CORS` في `server.ts` مثبَّت على `5173` فقط                  | أي منفذ ويب آخر يُرفض                     |

| 5   | `exportPdf`/`printDocument` يفتحان نافذة منبثقة + حوار طباعة | يحجبان الصفحة ويكسران تسجيل الفيديو       |

### وضع web-demo — كيف يعمل

```
pnpm dev:web
  ├─ API   : ENV_FILE=.env.web-demo  →  127.0.0.1:45699  (قاعدة dalaly_demo، مجلد بيانات server/data/web-demo)
  └─ Vite  : --mode web-demo         →  127.0.0.1:5199   (VITE_API_BASE_URL=http://127.0.0.1:45699/api)
```

العزل مضمون بأربع طبقات: ملف بيئة مختلف، قاعدة بيانات مختلفة، منفذ API مختلف، منفذ ويب مختلف، ومجلد بيانات مختلف. تشغيل `pnpm dev` (نسخة Electron) لا يقرأ أياً من ذلك.

